# H-002 — mensajes honestos al desbloquear con poca RAM: rojo → verde en QEMU (2026-11-04)

**Estado:** las dos opciones (ADR-009) funcionan en QEMU sobre una instalación real. Falta
la compuerta MATCH ×2 de la ISO con el cambio y la instalación hecha con 1 GiB de RAM
(la parte de H-002 que decide la RAM mínima).

## Entorno

- Disco `nimbo-install-sb.qcow2`: instalado el 4-nov desde la ISO de CI `17ee64c8…` con el
  lanzador cifrado, Secure Boot activo y el camino por defecto (initramfs-tools).
- Keyslot 0 (contraseña de la persona): argon2id, **1 048 576 KiB**. Keyslot 1 (clave
  generada para la prueba): argon2id, ~713 MiB.
- **Verde:** los tres ficheros de la receta se instalaron en el sistema con
  `probar-h002.sh` (mismas rutas y permisos que `config/includes.chroot/`) y se regeneró el
  initrd con `update-initramfs`, como hace el instalador. Las salidas `OK` las confirmó Juan
  José en pantalla.
- Arranques sin pantalla con `medir-desbloqueo.sh`, que teclea la clave de prueba. Para el
  verde con poca RAM se usó `--teclear-tras 15`: el aviso nuevo ocupa varias líneas encima
  del prompt y la detección automática del prompt no lo reconoce.

## Resultado

| RAM | Rojo (antes) | Verde (después) |
|---|---|---|
| 1024 MiB | `Not enough available memory to open a keyslot.` → `cryptsetup failed, bad password or options?` | **Antes del prompt:** *"nimbo: AVISO: desbloquear este disco necesita unos 1024 MiB de memoria y ahora hay unos 615 MiB libres. Es probable que falle por falta de memoria aunque la contraseña sea correcta."* **Tras teclear:** *"nimbo: AVISO: el disco no se pudo abrir: no hay memoria libre suficiente para el cifrado (argon2id). Esto NO significa que la contraseña sea incorrecta. Este equipo necesita más RAM…"* |
| 1280 MiB | `Out of memory: Killed process (cryptsetup)` → `bad password or options?` | Aviso previo (unos 856 MiB libres) y, tras el OOM-kill de `cryptsetup.real`: *"…el sistema detuvo el desbloqueo por falta de memoria. Esto NO significa que la contraseña sea incorrecta…"* |
| 1536 MiB | desbloquea | desbloquea, **sin aviso** (no hay falso positivo) |
| 2048 MiB | desbloquea | desbloquea, **sin aviso** |

Las capturas muestran la "ñ" y las tildes bien dibujadas en la consola del initrd.

## Límites

- El `cryptsetup failed, bad password or options?` de Debian **sigue apareciendo** después de
  nuestro mensaje. Quitarlo exigiría parchear `cryptroot`, y se decidió no hacerlo
  (ADR-009).
- Solo cubre initramfs-tools. Tras `nimbo-tpm-setup` el arranque usa dracut y
  systemd-cryptsetup, con sus propios mensajes.
- El aviso previo compara con `MemAvailable` en ese instante. Con esta VM no dio falsos
  positivos ni falsos negativos (avisó a 1024 y 1280, que fallan; calló a 1536 y 2048, que
  abren). En otro hardware el margen puede ser distinto.
- Las capturas que podrían mostrar la clave de prueba no se versionan (los directorios
  `medicion-desbloqueo-*` los ignora git).
