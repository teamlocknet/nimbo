# Evidencia — cómo instala `apt` un lote en una VM Debian 12 (11-nov-2026)

**Quién:** Emmanuel, con Claude Code manejando la VM `nimbo-pruebas` (Debian 12.15). Paquetes de
juguete `nimbo-prueba-bajada` 2.0 y 1.0 construidos con `dpkg-deb`; ninguna clave interviene
(esto mide solo el paso de `apt`, después de la verificación de la firma).

## 1. Hallazgo: `--no-download` rompe la instalación de `.deb` locales

| Orden (como root) | Resultado |
|---|---|
| `apt-get install --no-download -y /tmp/bajada/np_2.0_all.deb` | ❌ `E: Internal Error, Pathname to install is not absolute 'nimbo-prueba-bajada_2.0_all.deb'` (código 100) |
| `apt-get install -y /tmp/bajada/np_2.0_all.deb` | ✅ `Configurando nimbo-prueba-bajada (2.0)` |

`instalar` usaba `apt-get install --no-download -y <copias>`: **nunca habría instalado un lote
real**. Las pruebas unitarias no lo veían porque sustituyen `apt-get` por un doble.

**Arreglo:** `apt-get install -y -o Dir::Etc::sourcelist=<vacío> -o Dir::Etc::sourceparts=<vacío>`.
Sin fuentes remotas, `apt` no puede descargar nada; lo que no venga en el lote ni esté
instalado hace fallar la instalación.

## 2. La bajada de versión (`pruebas/prueba-bajada-version.sh`, mismas opciones que `instalar`)

```
$ apt-get install -y <sin fuentes> ./nimbo-prueba-bajada_2.0_all.deb
Configurando nimbo-prueba-bajada (2.0) ...
(código 0)

$ apt-get install -y <sin fuentes> ./nimbo-prueba-bajada_1.0_all.deb   # lote VIEJO
Se DESACTUALIZARÁN los siguientes paquetes:
  nimbo-prueba-bajada
E: Se instalaron versiones anteriores de algunos paquetes y se utilizó -y sin --allow-downgrades.
(código 100)

$ dpkg-query -W nimbo-prueba-bajada
nimbo-prueba-bajada	2.0
```

**VEREDICTO: PASA** — `apt` se niega a bajar de versión y la 2.0 sigue instalada.
