# Evidencia — la USB en la ISO instalada: no se monta sola; el montaje a mano en solo lectura funciona (17-nov-2026)

**Quién:** Emmanuel, con Claude Code manejando la VM (la contraseña de `sudo` la tecleó
Emmanuel). **Por qué:** revisión de #93 por Juan José: la ISO no trae `udisks2` ni `gvfs`, y
`polkitd` se quita al instalar, así que la guía no podía decir "ábrela en el gestor de archivos".

## Entorno

- ISO de `main` `eb3bc36` (`b0df8d62…`, MATCH ×2) instalada con Calamares cifrado en VirtualBox
  (VM `nimbo-iso-nav`). Controlador USB OHCI y un **disco USB virtual** de 128 MB, conectado y
  desconectado **en caliente** desde el host (`VBoxManage storageattach`).
- La USB se formateó en la VM como una memoria normal (una partición FAT, etiqueta `NIMBOUSB`)
  con un lote de prueba en `nimbo-0.1.2/`: el `.deb` de juguete de `preparar-lotes-rnf03.py`,
  su `MANIFIESTO` y un `MANIFIESTO.asc` que **no** es una firma (a propósito).

## Resultados

| Comprobación | Resultado |
|---|---|
| Paquetes en el instalado ([captura](2026-11-17-usb-iso/1-paquetes.png)) | `udisks2`, `gvfs`, `gvfs-backends`, `polkitd`, `thunar-volman`: **no instalados**; `thunar` y `dosfstools` sí; `gpg` no (solo `gpgv`) |

| `nimbo-update-offline verificar /mnt/nimbo-0.1.2` (sin `sudo`) | lee la USB; `RECHAZADO: firma inválida…`, código 1 (esperado: el lote no está firmado por nimbo) |
| `sudo nimbo-update-offline instalar /mnt/nimbo-0.1.2` | copia, verifica la copia: `RECHAZADO… No se instaló nada.`, código 1; ningún error por la USB en solo lectura |
| `touch /mnt/x` | "Sistema de ficheros de sólo lectura": nada puede modificar la USB |
| `sudo umount /mnt` | desmontada |

**Confirmado lo que sospechaba Juan José.** Las guías (`actualizacion-sin-conexion.md`,
`guia-design-partner.md` paso 6 y el README del paquete) pasan al montaje a mano en solo lectura.

## Instalación aceptada desde la USB en solo lectura (17-nov, 22:35)

Con el **lote firmado por Juan José** con la clave de release (el de la Parte 2 de RNF-03).
Lo pasó en `lote-firmado-rnf03-2026-11-16.tar.gz`, y antes de usarlo se comprobó en el host:

| Comprobación | Resultado |
|---|---|
| SHA-256 del `.tar.gz` | `9c37d48fa900389a9442abca832544b7245054b97b561f532a23b33a65f83848` (el que dio Juan José) |
| Contenido | `20-firmado-release/` con `MANIFIESTO`, `MANIFIESTO.asc` y `nimbo-rnf03-prueba_1.0_all.deb`; nada más |
| `.deb` | SHA-256 `4be86498…71af`, el del `MANIFIESTO` |
| `MANIFIESTO` y firma | idénticos byte a byte a `repro/evidencia/2026-11-16-rnf03-sin-red/parte2-lote-firmado-MANIFIESTO.{txt,asc}` |
| `gpgv` con `debian/keyrings/nimbo-actualizaciones.gpg` | `GOODSIG` + `VALIDSIG` `58A7B1C5…11A834D130E69451` (subclave de la clave de release) |

El lote entró en la VM por el teclado virtual (base64; dentro dio el mismo SHA-256) y se copió a
la USB. Después se desconectó y volvió a conectar la USB y se siguió **la guía, tal cual**:

| Paso | Resultado |
|---|---|
| antes | `dpkg -s nimbo-rnf03-prueba` → no instalado |
| `sudo mount -o ro /dev/sdb1 /mnt` | montada `ro` ([captura](2026-11-17-usb-iso/5-lote-firmado-instalar.png)) |
| `nimbo-update-offline verificar /mnt/20-firmado-release` (sin `sudo`) | **`ACEPTADO: 1 paquetes con firma válida`**, código 0 ([captura](2026-11-17-usb-iso/4-lote-firmado-verificar.png)) |
| `sudo nimbo-update-offline instalar /mnt/20-firmado-release` | apt instala desde la **copia** `/tmp/nimbo-update-…/`, no desde `/mnt`: **`nimbo-update-offline: actualización instalada.`**, código 0 |
| `dpkg -s nimbo-rnf03-prueba` | **`Status: install ok installed`**, `Version: 1.0` ([captura](2026-11-17-usb-iso/6-lote-firmado-instalado.png)) |
| `touch /mnt/x` | "Sistema de ficheros de sólo lectura" |
| `sudo umount /mnt` | desmontada |

En la captura 4, el principio de la línea sale en mayúsculas (`SCLEAR: SLBLK…`, "orden no
encontrada"): el teclado virtual dejó pulsada Mayús. Solo afectó a `clear` y `lsblk`, que se
repitieron en el paso siguiente (captura 5).

**Cerrado:** con una USB montada a mano en solo lectura, el procedimiento de la guía verifica e
instala un lote firmado por nimbo sin red.

**Observación (sin efecto):** apt imprime `N: Download is performed unsandboxed as root as file
'/tmp/nimbo-update-…/….deb' couldn't be accessed by user '_apt'`. Es una nota de apt: el
directorio temporal de la copia es `0700` de root y el usuario `_apt` no puede leerlo. La
instalación termina bien. Si confunde al Design Partner, se podría crear la copia legible para
`_apt`. No se cambia antes de la demo.

## Nota sobre el lote de prueba

Primero se intentó reconstruir el lote a partir de `preparar-lotes-rnf03.py`, pero el `.deb` de
juguete **no es reproducible**: `tarfile` en modo `w:gz` escribe la hora actual en la cabecera
gzip, aunque el comentario dice que sale igual en cada ejecución. Lo corrige Juan José, con su
test en rojo, después de la demo del 18-nov.
