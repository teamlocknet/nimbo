# Evidencia — la USB en la ISO instalada: no se monta sola; el montaje a mano en solo lectura funciona (17-nov-2026)

**Quién:** Emmanuel, con Claude Code manejando la VM (la contraseña de `sudo` la tecleó
Emmanuel). **Por qué:** revisión de #93 por Juan José: la ISO no trae `udisks2` ni `gvfs`, y
`polkitd` se quita al instalar, así que la guía no podía decir "ábrela en el gestor de archivos".

## Entorno

- ISO de `main` `eb3bc36` (`b0df8d62…`, MATCH ×2) instalada con Calamares cifrado en VirtualBox
  (VM `nimbo-iso-nav`). Controlador USB OHCI y un **disco USB virtual** de 128 MB, conectado y
  desconectado **en caliente** desde el host (`VBoxManage storageattach`).
- La USB se formateó en la VM como una memoria normal (una partición FAT, etiqueta `NIMBOUSB`)
  con un lote de prueba en `nimbo-0.1.2/`: el `.deb` de juguete de `preparar-lotes-rnf03.py`,
  su `MANIFIESTO` y un `MANIFIESTO.asc` que **no** es una firma (a propósito).

## Resultados

| Comprobación | Resultado |
|---|---|
| Paquetes en el instalado ([captura](2026-11-17-usb-iso/1-paquetes.png)) | `udisks2`, `gvfs`, `gvfs-backends`, `polkitd`, `thunar-volman`: **no instalados**; `thunar` y `dosfstools` sí; `gpg` no (solo `gpgv`) |
| USB conectada en caliente ([captura](2026-11-17-usb-iso/2-usb-conectada-sin-montar.png)) | el kernel la ve (`sdb`, `TRAN=usb`; `sdb1` `vfat` `NIMBOUSB`), pero **no se monta**, `/media/` **vacío** y **Thunar no la muestra** en "Dispositivos" |
| `sudo mount -o ro /dev/sdb1 /mnt` ([captura](2026-11-17-usb-iso/3-montaje-solo-lectura.png)) | montada `ro` |
| `nimbo-update-offline verificar /mnt/nimbo-0.1.2` (sin `sudo`) | lee la USB; `RECHAZADO: firma inválida…`, código 1 (esperado: el lote no está firmado por nimbo) |
| `sudo nimbo-update-offline instalar /mnt/nimbo-0.1.2` | copia, verifica la copia: `RECHAZADO… No se instaló nada.`, código 1; ningún error por la USB en solo lectura |
| `touch /mnt/x` | "Sistema de ficheros de sólo lectura": nada puede modificar la USB |
| `sudo umount /mnt` | desmontada |

**Confirmado lo que sospechaba Juan José.** Las guías (`actualizacion-sin-conexion.md`,
`guia-design-partner.md` paso 6 y el README del paquete) pasan al montaje a mano en solo lectura.

## Lo que no se pudo demostrar aquí

Una instalación **aceptada** desde la USB en solo lectura: necesita un lote firmado con la clave
de release. No se pudo reutilizar el de RNF-03 (Parte 2): el `.deb` de juguete **no es
reproducible**. `tarfile` en modo `w:gz` escribe la hora actual en la cabecera gzip, aunque el
comentario de `preparar-lotes-rnf03.py` dice que sale igual en cada ejecución. Se buscó la hora
del `.deb` firmado (`4be86498…`) segundo a segundo en 48 h y con las tres versiones del script,
sin éxito.

El código instala siempre desde la **copia** verificada, nunca desde la USB
(`test_instalar_verifica_copias_e_instala_sin_red`), y ahora un test lo fija con el lote en solo
lectura (`test_instalar_con_el_lote_en_solo_lectura`). Para cerrarlo con evidencia: repetir con
el lote firmado de Juan José.
